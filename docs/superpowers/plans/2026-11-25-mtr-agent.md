# MTR Polyglot Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build, verify and publish a reproducible Hong Kong metro multilingual Agent portfolio.

**Architecture:** A deterministic offline Agent orchestrates bounded session memory, intent rewriting, evidence retrieval and line-aware graph routing. Optional adapters add multilingual embeddings, reranking, LLM synthesis, Redis and official MCP without making the demo depend on them.

**Tech Stack:** Python 3.11+, FastAPI, Pydantic, PyMuPDF, pytest, Ruff, optional sentence-transformers/Redis/MCP.

**Spec:** `docs/superpowers/specs/2026-11-25-mtr-agent-design.md` (approved by user: 按方案直接做).

## Global Constraints

- Default demo requires no API keys, Redis or model download.
- Never publish resume, contacts, corporate documents or secrets.
- Synthetic transit data is not real-time operational advice.
- Resume metrics are unverified historical claims; report local measured scores separately.
- PDF geometry yields reviewable topology candidates, not inferred timetables.
- Push to `https://github.com/rryyyi/Agent-Project-3.git` after verification.

## Review Focus

- Reverse route direction and shared stations: no spurious transfer, minimum-time and minimum-transfer objectives differ correctly (Task 1).
- Negation/unknown station and ambiguous multi-turn follow-up: ask for clarification, no stale destination reuse (Task 3).
- Empty/noisy retrieval and injected instructions: no unsupported answer or execution (Tasks 2–3).
- Concurrent session access, expired state and data revisions: no cross-session or cache contamination (Task 3).
- Malformed PDF, missing optional services and unauthenticated API access: explicit errors, safe fallback or denial (Tasks 4–5).

## File map

`src/mtr_agent/`: `models.py` typed domain records; `knowledge.py` validated packaged data and aliases; `routing.py` line-aware Dijkstra; `retrieval.py` chunking/BM25/RRF/compression; `adapters.py` optional dense/rerank/LLM clients; `cache.py` bounded TTL plus optional Redis; `understanding.py` intent/alias/context rewriting; `agent.py` orchestration/session traces; `tools.py` shared validated tools; `api.py` service; `mcp_server.py` official SDK transport; `pdf.py` reviewable geometry extraction; `cli.py` demo/evaluation/benchmark entrypoints; `evaluation.py` metrics. `src/mtr_agent/data/` holds versioned synthetic JSON and evaluation JSONL. `tests/` contains behavior-focused unit and integration cases. `docs/` holds architecture, data/model/deployment/evaluation guides and reports.
